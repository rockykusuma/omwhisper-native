Shortcuts are yours to choose now, meetings actually notice your calls, and an app-wide stall
that made every shortcut feel broken is gone.

## If shortcuts felt unreliable, this is why

Memory's window capture ran on the main thread. When it was switched on, the app spent up to
three seconds out of every five doing accessibility work where the interface, the global
shortcuts and Fn push-to-talk all live — so none of them could respond. Nothing was broken;
everything was waiting.

It now runs off the main thread. If dictation sometimes didn't start when you pressed the
shortcut, or the Fn key seemed dead, this was almost certainly why.

## Shortcuts you can change

Every shortcut is now yours to set: toggle dictation, Smart Dictation, Polish Selected Text and
Brain-dump. Record any combination, or switch one off entirely. Settings › General.

OmWhisper will tell you when a combination is already used by one of its own commands, or is
reserved by macOS. It deliberately does **not** claim to know about other apps' shortcuts —
that isn't something macOS lets an app find out, and a confident "no conflict" would be a
promise it couldn't keep. If a shortcut seems to do something unexpected, another app very
likely has the same one; pick different keys.

## Meetings notice your calls

Meeting detection used to look at window titles for words like "meeting" or "call". Modern
Teams puts the *meeting's name* in the title instead, so a real half-hour call could run with
no prompt at all — and the same flaw would have missed Zoom, whose audio runs in a helper
process the old check never looked at.

OmWhisper now asks the system which app is actually using your microphone. That's direct
evidence rather than a guess, it needs no extra permission, and it doesn't care what a vendor
renames their windows to.

- **Recording stops when the call does.** Hanging up now ends the recording on its own. This
  never worked reliably before.
- **Browser meetings count too** — Google Meet, Zoom and Teams in a browser tab. A browser is
  only treated as a call when it's actually on a meeting page, so an ordinary site that uses
  your microphone won't set anything off.
- **Missing a prompt is no longer the same as saying no.** If the prompt appears while you're
  still picking your microphone on a join screen and it times out, OmWhisper asks once more a
  minute later, then leaves you alone. Choosing "Not now" still means no for the whole call.
- **A recording you start by hand is named after the call**, not after whatever window happened
  to be in front — which was usually OmWhisper's own.

Meetings are off until you turn them on, recordings stay on your Mac, and they are never sent
to a cloud provider even when a cloud backend is selected for everything else.

## Chronicles

Your daily chronicle summarised every captured window, which on a busy day meant tens of
sequential model calls for one paragraph. Most of that work was thrown away again in the final
pass. It now picks the most substantial capture per app per fifteen minutes first.

Measured on the same day, same Mac, same model: **over twenty minutes, unfinished, down to
about two.** The result got *more* specific, not less — fewer lossy passes means more detail
survives. Generation now shows progress and can be cancelled; cancelling writes nothing.

The honest cost: a genuine burst of different work inside one fifteen-minute window in one app
collapses to a single entry. Window titles from the rest of that group are kept, which softens
it without removing it.

## Ollama

Three problems that only appeared once you used a larger model:

- **The first request to a big model always failed.** The timeout was 30 seconds; a model
  loading from cold took 36. Ollama unloads models after a few minutes idle, so "cold" is the
  normal case, not an edge case. Meeting summaries and chronicles now wait up to five minutes;
  dictation keeps the short timeout, because there a slow model costs you the polish and never
  your words.
- **"Couldn't reach Ollama. Is it running?" when it plainly was.** Every failure was reported
  as unreachable. A timeout now says it timed out.
- **Reasoning models returned nothing.** gemma4, qwen3.5 and deepseek-r1 spend the same output
  budget on hidden reasoning as on the answer, and long inputs used all of it before writing a
  word. OmWhisper now turns that off for these requests.

A note on model size, learned the hard way: a bigger download is not a better model, and a
model that doesn't fit in your Mac's memory will make the whole machine crawl. On 16 GB,
something around 7B parameters is a sensible ceiling. Meeting Q&A needs roughly that much to
work at all — a 3B model answers "nothing relevant" to questions the transcript plainly
answers, which makes the feature look broken when it's the model that's out of its depth.

## Fixes

- Features that quietly fall back now say so. If AI polish returns nothing or Memory captures
  nothing repeatedly, Settings tells you which feature is degraded and why, instead of
  everything appearing to work while doing nothing.
- Meeting Q&A refused questions the transcript could answer, unpredictably — the same question
  might work on a second try.
- Summaries and chronicles showed `**bold**` as literal asterisks.
- Polish Selected Text displayed the previous dictation's words while it worked.
- Chronicle headings showed only the day, so regenerating produced two identical-looking
  entries. They now show when each was written.
- Memory search from the MCP server was exact-word only, while the app itself searched by
  meaning. Both now behave the same.
