One AI backend setting instead of two that disagreed, the model you picked is the model that
runs, and cloud dictation stops guessing when your sentence has finished.

## "Default" now means one thing

OmWhisper has five features that can use AI: dictation polish, Reply Assist, meeting summaries,
Chronicles and brain-dump. Each could be pointed at Apple Intelligence, at Ollama, at a cloud
provider, or left on **Default** — but "Default" quietly meant two different things depending on
which feature was asking, and **"Disabled" silenced two of the five while reading as global**.

There is now **one Default row** that every feature falls back to, and dictation polish has its
own on/off toggle instead of borrowing "Disabled" from a backend picker. Nothing about your
setup changes when you update — polish stays off if it was off, and each feature keeps whatever
you had chosen.

Default means *use what's on this Mac*, in the order that suits the job: dictation prefers Apple
Intelligence because it has to be fast, while summaries and Chronicles prefer Ollama because
they need room for a long transcript. On a stock install, switching polish on used to do
**nothing at all**, silently — that is fixed.

## The Ollama model you picked is the one that runs

If you set a feature to a specific Ollama model — say **Meetings → Ollama · qwen3.5** — that
choice could be thrown away, and a different model ran instead. Not occasionally: it was the
normal case, because the per-feature menu never wrote the shared model setting the old code
insisted on reading.

The row you set is now the row that runs, model included. Two related fixes came with it:

- **The Default row's own model was ignored**, so a model chosen there lost to the shared one.
- **The Settings screen couldn't reach Ollama** while the app itself could — it asked a
  different address than the one dictation used, so the model list came back empty and made a
  working setup look broken.

If a summary ever reads badly, the "Written by…" line under it names the exact model that wrote
it — that is what makes a bad summary diagnosable rather than mysterious.

## Cloud dictation stops guessing when you've finished

With a cloud transcription engine, OmWhisper used to stop sending audio, wait exactly one
second, and hang up — whether or not the service had finished sending your words back. A fixed
wait is a guess: too short and the end of a sentence is lost, too long and you wait for nothing.

It now waits for the service to actually say it's done, which is usually **faster** than the old
one-second pause. There's still a short ceiling so an unresponsive service can't hold up your
paste.

Two smaller things in the same path: OmWhisper was leaking a network session on every cloud
dictation, and errors from the service — a rate-limited key, an expired key, a dropped
connection — were being thrown away, so all three looked identical to silence. They now say what
happened.

## Also in this release

- **Polish nudges are honest.** The "turn on Apple Intelligence" prompt used to appear even when
  polish was deliberately switched off, and even when the feature was never going to use Apple
  Intelligence. It now appears only when that particular feature actually needs it.
- **A privacy rule in the settings migration**: an upgrade may make a feature more private than
  you left it, never less.
- **Onboarding**: choosing a backend during setup now also switches dictation polish on, rather
  than leaving you with a backend selected and nothing using it.

Under the hood there is also a script for recording a speech-accuracy corpus in your own voice,
and fixes to two internal diagnostics that were reporting failures on correct output. Neither
changes anything you'll see.
